# Doto Writing System — Skill 套件方案（v2 精简版）

> 基于 Bob Doto《A System for Writing》深度研读后设计，针对 Capacities Pro + MCP 用户的技能套件提案

---

## 一、书籍核心理解

Bob Doto 的《A System for Writing》是迄今为止对 Zettelkasten（卡片笔记法）最实用、最可操作的入门指南。与 Sönke Ahrens 的《How to Take Smart Notes》偏理论不同，Doto 的书是一本**"怎么做"手册**——每章末尾都有检查清单，配有大量笔记示例和工作流程图。

### 全书三大部分九章节结构

| 部分 | 章节 | 核心主题 |
|------|------|----------|
| **Part I: 捕捉** | Ch.1 临时笔记 | 随时捕捉转瞬即逝的想法，收入"收件箱" |
| | Ch.2 参考笔记 | 阅读时捕捉关键段落，搭建输入到输出的桥梁 |
| | Ch.3 主笔记 | 将想法提炼为原子化、可连接的永久笔记 |
| **Part II: 连接** | Ch.4 连接思想 | 在笔记间建立有上下文的关系，而非"链接堆砌" |
| | Ch.5 字母数字ID | Folgezettel 系统——非层级的导航机制 |
| | Ch.6 拥抱混乱 | 枢纽笔记与结构笔记——分布式网络的高层视角 |
| **Part III: 写作** | Ch.7 从笔记到写作 | ZK 引导写作但不替代写作 |
| | Ch.8 为读者写作 | 短内容→博客→文章→书籍的渐进式发布 |
| | Ch.9 写作管理 | 日记、创意日志(CLOG)、任务驱动项目管理 |

### Doto 方法论的 7 个核心差异点

1. **主笔记六要素**：标题、单一想法、链接、引用来源、使用记录、唯一ID
2. **"使用记录"是独特要素**：追踪每条笔记在何处被使用过
3. **批注（Marginalia）前置**：强调在书上直接写批注作为参考笔记的前置步骤
4. **"受控混乱"哲学**：拥抱非层级、自下而上的涌现式结构
5. **连接必须带上下文**：明确禁止"链接堆砌"（link dumping）
6. **分区标题后置**：只能在想法积累后后补，不能预先设定
7. **写作管理整合**：日记+CLOG+项目管理整合进 ZK 工作流

### 可持续性是第一原则

> "A Zettelkasten succeeds or fails based on sustainability." —— Bob Doto

所有设计决策——属性数量、skill 数量、操作摩擦——都要服从这个原则。每多一个非必要字段、每多一个冗余 skill，用户放弃的概率就高一分。

## 二、v2 架构：1 主入口 + 4 子 skill

### 命名说明

本套件以作者 **Bob Doto** 命名（`doto`），而非通用方法论名 `zettelkasten`。理由：

1. **与现有套件风格一致**：`fogg-habit`（作者+主题）、`youjie`（书名）均为作者/书名路线
2. **避免泛化陷阱**：这套方法论是 Doto 的特定解读，含六要素、受控混乱、批注前置等独家内容
3. **诚实命名**：叫 `zettelkasten` 会让人误以为是通用 ZK 方法论
4. **触发词兜底**：skill 名是 `doto`，触发词保留"zettelkasten/卡片笔记/ZK"，搜索性不受影响

### v1 → v2 的精简逻辑

v1 设计了 8 个子 skill，经审视存在过度设计。精简标准：

> **判断一个 skill 该不该独立**：(1) 有没有独立的触发场景？(2) 引导内容能否撑起一个文件？(3) 合并后会不会臃肿？(4) 用户记住 N 个入口的成本值不值？

按此标准砍掉了 4 个"伪独立"的模块：

| 被砍的 skill | 理由 | 归属 |
|-------------|------|------|
| 临时笔记模块 | 临时笔记就是"快记一句话"，没有独立引导需求 | 并入 `doto-create` |
| 参考笔记模块 | 参考笔记和主笔记是同一条流水线的不同阶段 | 并入 `doto-create` |
| Folgezettel 模块 | 分配 ID 是创建主笔记的子步骤，不是独立工作流 | 并入 `doto-create` |
| 写作管理模块 | CLOG/项目管理是写作的一部分 | 并入 `doto-write` |

核心原则：**子步骤不独立成 skill，只有独立工作流阶段才独立**。

### 各 skill 职责

| Skill | 合并了 v1 的什么 | 为什么值得独立 |
|-------|----------------|--------------|
| **`doto-create`** | 临时笔记 + 参考笔记 + 主笔记 + Folgezettel | "把想法变成规范笔记"是一条完整流水线，不管来源是灵感/阅读/对话，终点都是原子化 Zettel。ID 分配是其中一步 |

### 2. `doto-create` — 笔记创建流水线（核心模块）

**文件位置**: `~/.workbuddy/skills/doto/skills/doto-create/SKILL.md`

**触发场景**: 任何"我要记下这个想法"的场景，无论来源是灵感、阅读、对话还是观察

**核心设计**：按输入类型分流，但终点都是规范的 Zettel

#### 三种输入路径

**路径 A：临时想法（→ Fleeting Note → Zettel）**

```
用户: "我有个想法：原子笔记提升可连接性"

AI 流程:
1. saveToDailyNote("原子笔记提升可连接性")  ← 快速捕捉到 Daily Note
2. 询问: 这个想法现在要展开成主笔记，还是先放在收件箱?
3. 若展开 → 路径 C
4. 若暂存 → 完成，标记 #inbox 待后续处理
```

**路径 B：阅读笔记（→ Reference Note → Zettel）**

```
用户: "我在读《思考，快与慢》第 119 页，关于锚定效应"

AI 流程:
1. 先创建/找到对应的 Reference Note（createObjectViaMd 或 search）
   正文结构:
   ### p.119 — 锚定效应
   > {原文引用}
   **批注**: {为什么重要，与什么相关}
2. 询问: 这段值得变成自己的主笔记吗?
3. 若是 → 路径 C，从 Reference Note 转化
4. 若否 → 保留 Reference Note 作为阅读索引
```

**路径 C：直接创建主笔记（所有路径的终点）**

这是最关键的部分——无论想法来自哪里，最终都要变成符合六要素的 Zettel。

```
AI 引导流程:
Step 1: 重写 — "用你自己的话完整句子表述这个想法"
  (不是复制原文，是消化后的再表达)

Step 2: 原子化检查 — "这条包含几个想法?"
  若多个 → 建议拆成多条 Zettel
  若单一 → 继续

Step 3: 分配 ID（如果用 Folgezettel）
  询问: 这和你已有笔记有关吗?
  - 无关 → 新主题: {下一个可用数字}.1
  - 是延伸 → 在某条 ID 后加字母: 如 3.1 → 3.1a
  - 同主题独立想法 → 该主题下一个数字: 如 3.1 → 3.2
  (不强制，用户可选只用 @链接 不用 ID)

Step 4: 建立连接 — search 找相关笔记，建议带上下文的连接
  "这条和 @{已有Zettel} 相关吗? 如果是，为什么?"

Step 5: 拟标题 — 简洁概括想法

Step 6: 标注来源 — 写在 source 属性或正文末尾

Step 7: createObjectViaMd 创建 Zettel
```

#### 主笔记六要素 → Capacities 映射

| Doto 六要素 | Capacities 实现 | 是否必须 |
|------------|----------------|---------|
| 1. 标题 | 对象标题 | ✅ 必须 |
| 2. 单一想法 | 正文 body | ✅ 必须 |
| 3. 链接 | `@` 链接到 Zettel（带上下文说明） | ✅ 至少 1 个 |
| 4. 引用/来源 | `source` 属性或正文末尾 | ✅ 原创/阅读/对话都标 |
| 5. 使用记录 | backlinks 自动生成；写作时手动补 | 可选 |
| 6. 唯一 ID | `id` 属性（如 `3.2a`） | ✅ 必须 |

#### Folgezettel ID 系统（作为 doto-create 的内置说明）

**核心定位**: 为笔记赋予永久身份，实现精确引用和思想链追溯。

**ID 规则**:
```
{主题号}.{分支号}{字母延伸}

示例树:
1  (主题: 认知偏差，标题后补)
1.1  锚定效应
  1.1a  锚定效应在定价中的应用
  1.1b  锚定效应的神经机制
1.2  确认偏误
1.3  可得性启发
```

**分配决策**:
- 新主题 → `{下一个可用数字}.1`
- 延伸某条 → 该 ID 后加字母
- 同主题独立 → 该主题下一个数字

**成熟度判断**: ID 越长（如 `7.16a1b2`），说明这条思想线越成熟，可能值得写作。

#### 章末检查清单（来自 Doto）
- [ ] 是否只包含一个想法？（原子性）
- [ ] 是否用自己的话表述？（非复制）
- [ ] 是否有至少一个带上下文的链接？
- [ ] 是否标注了来源？
- [ ] 标题是否简洁概括了想法？
- [ ] 是否分配了 Folgezettel ID？

### 3. `doto-connect` — 连接思想

**文件位置**: `~/.workbuddy/skills/doto/skills/doto-connect/SKILL.md`

**触发场景**: 用户想在新笔记与已有笔记间建立连接，或想发现笔记间的隐藏关联

#### 连接的本质
ZK 不是笔记集合，而是**思想网络**。连接是产生新见解和构建长篇论证的关键。

#### 连接类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 延伸 | 对已有想法的进一步展开 | "这条是 @{Zettel} 的延伸，因为..." |
| 对比 | 与已有想法形成对比 | "与 @{Zettel} 不同，我认为..." |
| 因果 | 解释因果关系 | "@{Zettel} 中的现象可以用 @{Zettel} 解释" |
| 举例 | 为已有想法提供例证 | "@{Zettel} 的理论表现为..." |
| 质疑 | 挑战已有想法 | "@{Zettel} 的假设忽略了..." |
| 跨域 | 跨领域应用 | "@{Zettel} 的模式也出现在生物学中" |

#### 核心原则：禁止链接堆砌

```
✅ 好的连接: @{Zettel} — 这条的"原子性"原则与"模块化"思想一致
❌ 坏的连接: @{Zettel} @{Zettel} @{Zettel}  (没有任何上下文)
```

#### AI 辅助连接流程

```
1. search("当前笔记的关键词") → 找到相关 Zettels
2. 对每条候选，生成连接上下文建议:
   "这条和 @{Zettel} 相关吗? 建议连接原因: {AI 分析的潜在关联}"
3. 用户确认后，appendMdToObject 在当前笔记添加连接
   (同时在被连接笔记产生 backlink)
```

#### 发现连接的技巧
1. **提问法**: 和什么相似？对立？延伸？
2. **潜台词法**: 读出想法背后的潜台词
3. **跨域法**: 能否应用到完全不同的领域？
4. **追溯法**: 沿已有链接反向追溯
5. **即使牵强也连**: 未来可能带来意外洞见

#### 枢纽笔记（Hub Notes）vs 结构笔记（Structure Notes）

| | Hub Note | Structure Note |
|--|---------|---------------|
| **类比** | 高速公路交汇处 | 目录/大纲 |
| **功能** | 找思维链（定位入口） | 发展思维链（组织论点） |
| **内容** | 列出各分支起点的 Zettel 链接 | Zettel 按逻辑排列 + 过渡段落 |
| **创建时机** | 某主题积累 8-10 条 Zettels 后 | 准备围绕某主题写作时 |
| **Capacities 对象** | Hub Notes（建议新建） | Structure Notes（建议新建）|

#### 章末检查清单
- [ ] 每个链接是否有上下文说明？
- [ ] 是否尝试了至少一种跨领域连接？
- [ ] 是否避免了链接堆砌？
- [ ] 该主题 Zettels 是否多到需要建 Hub Note？

### 4. `doto-write` — 从笔记到写作（含管理）

**文件位置**: `~/.workbuddy/skills/doto/skills/doto-write/SKILL.md`

**触发场景**: 用户想将笔记转化为文章、博客、推文或书籍；或想追踪写作进度

#### ZK 的引导角色
> "A zettelkasten will not tell you what to write."

ZK 可以**指向**写作方向：
- 高连接密度区域 = 你在某个话题上积累了足够多的想法
- 参考笔记展示什么吸引了你的注意
- 结构笔记提供写作基础

但**不会替你写作**。

#### 渐进式发布管道

```
主笔记集群 → 短内容(推文) → 博客 → 长文章 → 书籍
     ↑                              │
     └──── 反馈生成新想法 ←──────────┘
```

| 形式 | 来源 | 目的 |
|------|------|------|
| 短内容 | 单条 Zettel | 快速测试想法，获得反馈 |
| 博客 | 主题 Zettel 集群 | 围绕主题的连贯作品 |
| 长文章 | 多个 Structure Note | 更严谨的论证 |
| 书籍 | 多篇文章整合 | 系统性输出 |

#### 从笔记到草稿的工作流

```
1. 选题: 找连接密度高的笔记集群 (search + 人工判断)
2. 创建 Structure Note: 把相关 Zettels 按论点排列
3. 审查: 检查逻辑断裂或论据缺失
4. 补充: 识别需要新增的笔记 → 回到 doto-create
5. 起草: 重写而非复制——让想法适应文章论证流
6. 编辑: 删减、重组、添加过渡
7. 发布: 选择形式
8. 记录使用: 更新每条 Zettel 的 used_in (或依赖 backlinks)
```

#### 写作管理（原写作管理模块合并进来）

**每日日记**（Capacities Daily Note）:
```
## 收件箱
- {临时想法}

## 今日活动
- {做了什么}

## 明日建议
- {下次从哪继续}
```

**CLOG（创意日志）** — 每次写作会话后:
```
## 本次完成
## 待处理
## 下次开始建议
```

**任务驱动项目管理**（有截止日期时）:
```
定义项目 → 头脑风暴任务 → 收集资源(从ZK) → 只做今天的任务 → 记录进展(到CLOG)
```

#### 写作哲学
> "Writing is bigger than writing."

写作包含：捕捉想法 → 提炼笔记 → 连接关联 → 组织论点 → 起草 → 编辑 → 发布 → 获取反馈。

#### 章末检查清单
- [ ] 是否找到了足够成熟的笔记集群？
- [ ] 是否创建了 Structure Note 作为大纲？
- [ ] 草稿是否重写了笔记内容（而非复制）？
- [ ] 是否更新了 Zettel 的使用记录？
- [ ] 是否在 CLOG 记录了进度和"下次从哪继续"？

### 5. `doto-audit` — 质检与体检（新增）

**文件位置**: `~/.workbuddy/skills/doto/skills/doto-audit/SKILL.md`

**触发场景**: 体检现有笔记是否符合标准；或写新笔记前质检

**核心定位**: 不是"搬运工"，是"质检员"。**AI 只诊断不动手**，避免破坏笔记。

#### 双模式设计

**模式 A：体检模式（一次性，针对旧笔记）**

触发: "帮我看看现有笔记合不合格"

```
AI 流程:
1. search 拉取 Zettels（分批，每次一个关键词主题）
2. 对每条按六要素打分:
   - 原子性: 是否只含一个想法?
   - 原创: 是否用自己的话?
   - 连接: 是否有带上下文的链接?
   - 来源: 是否标注出处?
   - 标题: 是否简洁概括?
3. 分类输出体检报告:

   ✅ 保持原样（符合标准）: 12 条
   🔧 小修即可（补标题/补连接）: 8 条
      - "{标题}" → 缺连接，建议连到 @{某条}
   ✂️  建议拆分（含多个想法）: 3 条
      - "{标题}" → 可拆成 {N} 条原子 Zettel
   📦 降级为 Reference Note: 4 条（是摘抄不是原创）
   🗑️  建议删除: 2 条（与 ZK 目标无关）
4. 你决定执行哪些 → AI 协助操作
```

**核心原则**: 遇到再处理，不批量重构。只挑你真正会用到的旧笔记改。

**模式 B：质检模式（日常，写新笔记时）**

触发: 用户用 `doto-create` 创建 Zettel 前，自动跑一遍检查。

```
检查清单:
[ ] 原子性 — 这条只包含一个想法吗?
[ ] 原创性 — 是用你自己的话写的吗?
[ ] 连接 — 有至少一个带上下文的链接吗?
[ ] 来源 — 标注出处了吗?
[ ] 标题 — 简洁概括了吗?

不通过的项目 → 提示用户补充
```

#### 质检的价值不只是"整理"

1. **学习方法论**: 拿真实笔记逐条点评，比读十遍书都管用
2. **建立手感**: 反复质检后，你自然学会"什么是好的原子笔记"
3. **降低启动摩擦**: 把"我的笔记可能不规范"的焦虑变成具体清单

#### 章末检查清单（来自 Doto）
- [ ] 体检报告是否让你清楚了哪些笔记值得保留？
- [ ] 是否避免了批量重构的冲动？
- [ ] 新笔记质检是否融入了日常流程？

## 六、技术实现方案

### 文件结构

```
~/.workbuddy/skills/doto/
├── SKILL.md                              # 主入口 / 路由器
├── references/
│   ├── book-summary.md                  # 《A System for Writing》全书摘要
│   ├── note-templates.md                # 所有笔记模板汇总
│   ├── checklists.md                    # 各章节检查清单汇总
│   └── glossary.md                      # ZK 术语表（中英对照）
├── skills/
│   ├── doto-create/
│   │   └── SKILL.md                      # 笔记创建流水线（核心）
│   ├── doto-connect/
│   │   └── SKILL.md                      # 连接思想
│   ├── doto-write/
│   │   └── SKILL.md                      # 从笔记到写作（含管理）
│   └── doto-audit/
│       └── SKILL.md                      # 质检与体检
```

### 实现优先级

| 优先级 | Skill | 理由 |
|--------|-------|------|
| P0 | `doto`（主入口） | 套件核心 |
| P0 | `doto-create` | 笔记创建是 ZK 的核心动作 |
| P1 | `doto-connect` | 连接是 ZK 的灵魂 |
| P1 | `doto-audit` | 体检旧笔记能立刻产生价值，帮助用户启动 |
| P2 | `doto-write` | 写作是最终产出，但需要笔记积累后才有意义 |

### 与现有套件的架构一致性

本套件采用 1 主入口 + N 子 skill 的架构，与你已有的三套 skills（systems-thinking、fogg-habit、youjie）保持一致风格。

### 平台无关化

虽然本方案深度集成 Capacities MCP，但 skill 的方法论核心（六要素、连接原则、写作流程）是工具无关的。Capacities 相关的内容会单独标注，方便未来适配其他工具。

## 七、v1 → v2 精简记录

### 砍掉的 4 个 skill 及理由

| 被砍 skill | 原以为独立 | 实际是 | 归属 |
|-----------|-----------|--------|------|
| 临时笔记模块 | 临时笔记是独立动作 | 只是"快记一句话"，无独立引导需求 | 并入 doto-create 路径 A |
| 参考笔记模块 | 参考笔记是独立类型 | 参考笔记→主笔记是同一流水线阶段 | 并入 doto-create 路径 B |
| Folgezettel 模块 | ID 系统是独立导航工具 | 分配 ID 是创建主笔记的子步骤 | 并入 doto-create 内置说明 |
| 写作管理模块 | 写作管理是独立工作流 | CLOG/项目是写作的一部分 | 并入 doto-write |

### 判断标准（供未来设计参考）

1. **有没有独立触发场景？** 用户会不会专门想做"这件事"？
2. **引导内容能否撑起一个文件？**
3. **合并后会不会臃肿？**
4. **用户记住 N 个入口的成本值不值？**
